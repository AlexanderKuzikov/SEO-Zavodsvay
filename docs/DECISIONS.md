# SEO-Zavodsvay — DECISIONS

<!-- Append-only. Формат фиксирован. -->

## 2026-08-05: Границы проекта

**Контекст:** Накопление SEO-данных для zavodsvay.ru (Wordstat-выгрузки, ядро, аудиты, синхронизация с SerpWatcher) засоряет репозиторий сайта. Решено выделить отдельный проект.

**Решение:** Создать `SEO-Zavodsvay` — только данные и скрипты анализа. Сайт остаётся в `Zavodsvay-Static`, мониторинг позиций — в `SerpWatcher`. Связка: ядро (SSOT) → скрипт генерации → `SerpWatcher/data/projects.json`.

**Альтернативы:** вести всё в `Zavodsvay-Static` (засорение продукта); расширять `SerpWatcher` аналитикой (смешение ролей инструмента и данных).

**Trade-off:** дублирование `core.csv` в обоих проектах — SSOT здесь, зеркало в сайте по необходимости.

## 2026-08-05: Формат семантического ядра

**Контекст:** Ядро из `Zavodsvay-Static` имело колонки `запрос;приоритет;тип;приёмник`, без частотности.

**Решение:** Колонки ядра: `запрос;приоритет;тип;приёмник;частота`. Частота — Wordstat за месяц (все регионы, все устройства). Пустая частота → «нет данных», не 0.

**Альтернативы:** отдельный файл частот; JSON вместо CSV.

**Trade-off:** CSV проще диффить и править руками; частота от прошлого месяца может устаревать — дата выгрузки в имени файла `data/wordstat/`.

## 2026-08-05: Монитор реальных позиций на API Вебмастера

**Контекст:** Search API (SerpWatcher) отдаёт другой поток ранжирования, чем браузерная выдача Яндекса — для локально-коммерческих запросов расхождение критично (сайт может отсутствовать в топ-100 API при реальной 2-й странице в браузере). Нужен источник «правды».

**Решение:** Второй монитор — `scripts/webmaster_monitor.py` в SEO-Zavodsvay. Использует `query-analytics/list` с `text_indicator=URL`: позиции **страниц-приёмников** (из ядра) по срезам регион (Пермский край 11108 / все регионы) × устройство (desktop / mobile_and_tablet). Данные: `data/webmaster/data.json`, окно 14 дней (лимит API), срез заменяется целиком при успешном ответе. UI — статический SPA (`ui/`, vanilla + uPlot, светлая тема на дизайн-токенах).

**Отклонение от ADR-001** («мониторинг позиций — в SerpWatcher»): Вебмастер даёт данные иной природы (официальная агрегированная статистика по дням, только свой сайт, только по запросам с показами) — это данные, а не SERP-скрейпинг, поэтому живут в проекте данных. Порт в SerpWatcher возможен после рефакторинга хранилища (open #2 там).

**Альтернативы:** движок в SerpWatcher (риск сломать работающее, конфликт двух движков при мерже); RU SaaS (Пиксель Тулс/Топвизор — платно, данные на чужой стороне); self-hosted парсинг (капча, прокси).

**Trade-off:** два источника позиций (API — тренды, Вебмастер — правда); данные Вебмастера запаздывают ~1 день и есть только по запросам с реальными показами.
